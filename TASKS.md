## Decisions (user)
- Mosaic magic calculator: a spell builder page plus a chatbox.
- Stack: Angular (front end), Java (backend), Python (chat service, local runs through the `.venv`).
- Four containers: proxy, backend, chat service, Postgres (mounted volume).
- Everything in Postgres: mosaic table (cost data as declarative data), forms, material groups, characters, saved spells, audit table. Every write goes through the DAO and is audited.
- Chat service calls the backend's MCP server; login on the MCP link is one API key for the chat service; the chat service asks the backend to validate the player's session on each chat request; every logged-in player may use the chat.
- Page language: Hungarian. Admins (admin role) edit mosaic data.
- Power rises only in fixed whole steps (cost = base MP + k x denominator of +E/MP, E = base E + k x numerator).
- Tier range is 0 to 5. Basic magic (Alapvarázslatok) mosaics have tier 0, so every character meets it; no basic mosaic uses a form. A character with no entry for a school has tier 0 there.
- Backend and engine use Java 26. The proxy stays nginx and keeps the /api and /chat prefixes.
- Overspending MP (user decision): a cast with more MP than the current MP is allowed (chaos magic). Current MP becomes 0; the backend reports the overspent MP and the schools of the spell, and the page shows them in a popup (phase 4). The calculate step also shows the overspend before casting. Which school carries which part of the overspend is not defined; only the list of schools is given.
- Docker (Colima + docker CLI + Compose) and PostgreSQL 17 are installed on this machine, started by hand (not at login).
